4. EVENT MAPPING
Ordinary catch and porch bell -> MINOR.
Secret area, restricted item, accepted blackmail, rejected blackmail -> SERIOUS.
The relationship state is captured before confrontation penalties. The next
proposal uses the updated relationship, without changing the scold personality.
Bell reconciliation does not invent an inappropriate wandering-catch opener.

5. SEQUENCING
One owner-scoped Reconciliation controller extends the existing SecretDialogue
queue. Opening/outcome -> scold -> safe return -> existing proposal -> existing
five-minute warning -> portal. Recorded durations and client completion signals
gate transitions, with a bounded recovery fallback if an acknowledgement is lost.
Duplicate catches are blocked while the conversation is active. Accepted blackmail
does not begin its outcome/scold until the selected reward is actually delivered.

6. RETURN HOME AND CONTROL
During confrontation the player stays near a captured anchor; camera angles remain
free. The bell brings Mother back with bounded pathfinding recovery. After the
scold, distant/unsafe players move to a collision-checked supported location near
the porch/door. Already-nearby players are not unnecessarily teleported. Failure
to find a safe return releases the conversation and uses the existing safe exit.
Logout suspends the presentation; rejoin resumes the full scold without reapplying
consequences. Death, departure and forced phase changes release the constraint.

7. NEXT ACTIVITY
Uses OtherMotherLoop's existing activity selection and lifecycle, preferring a
different activity. It does not replay welcome dialogue, create visit gifts,
increment visits, or erase earned rewards, exposure, counter-attributes or
blackmail transactions. All existing activities remain in the existing scheduler.

8. PORTAL CYCLE
The previous portal/window and pending search timer are removed. After proposal
and warning playback, the existing portal receives a new 6,000-tick (five-minute)
attendance window. Ignoring it invokes the existing missed-activity/search flow.

9. STORY OVERRIDES
Suspicion 1.0, SCRIPTED_TRAP and departure from the eligible visit phases prevent
normal reconciliation scheduling. A threshold confrontation also removes an old
activity window, and a threshold reached during proposal cancels that proposal.
IMPORTANT: this repository has no completed trapping/boss/button-eye/soul-trapped
story state machine to invoke. These are protective guards, not an implementation
of those missing storylines.

10. DEBUG CONTROLS

ordinary/secret/item/bell event buttons, accepted/rejected blackmail tests and
force-next-proposal. Shows conversation stage and proposal-pending status.

Blackmail tests require a genuine owned Blackmail Item and use the real reward UI.
Secret-area testing requires a generated secret room. Catch classification still
